## 第二步：公开失败驱动的有界重新定位

实现与回归提交：`1af0aca`，复用现有工具、图关系和 Unified Coding Session，没有新增独立 Agent 或放宽写权限。

宿主只根据完整公开验证结果计数：连续两次非零退出且没有超时、截断或跳过，才考虑调查。通过、运行环境未完成和无法确认的旧报告中断计数。恢复使用已保存公开报告，不从缺失字段推断失败或未消费额度。

调查入口来源为当前 SHA 下的公开诊断源码位置，或失败测试的实际运行时导入。诊断窗口没有包含文件顶部 imports 时，可先读取已观察到的失败测试；此时实现候选保持为空，不把测试位置认定为根因，也不认定范围不足。无关测试不会取得这项额度。

调查复用现有 ExplorationBudget、图解析和 Session：

- 全流程一次调查，最多 **两次读取、一次有根路径的搜索或图查询**。最多保留四个只读根路径。
- 读取取得完整且当前 SHA 一致的图节点后，可以沿已解析、非 type-only 的真实导入延续只读根路径；不额外读取，也不重置额度。外部、歧义、过期及未核实关系不能取得该路径。
- 调查 ID、消费、根路径及关系来源持久化；审批恢复、再次失败和新请求不能重新领取额度。旧消费无法确认时保持保守阻断。
- 原可选探索消费不变；新增调查仍接受 Scheduler、时间、token、步骤和逻辑工具硬限检查。探索关闭后仅复用现有一次证据刷新，不新增收尾或格式纠正机会。
- 读取、图关系和候选都不授予写权限。只有有效当前原文/SHA 支持的 `SCOPE_CONFLICT` 才能申请已有一次 Replan；Planner 判断因果关系，并产生新的 PLAN 审批。
