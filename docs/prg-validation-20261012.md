# PRG 首轮真实实验与 v2.4.0 验收

实验冻结提交为 `235b46f5dfb27a4a97202a1532f8d4909abd8133`，实验包版本为
**2.3.1**。2026-10-12 按 E05 → E06 → E10 各执行一次完整 PRG 流程，随后
为严格成功的 E05 执行一次 `legacy-dynamic` 对照。没有追加完整流程重试。

PRG 严格通过 **1/3（E05）**；E05 对照严格通过 **0/1**。按照事先约定的
“任一 PRG 案例严格通过且工程与保护回归通过”门槛，本地包版本升级为
**2.4.0**。实验完成后仅调整版本声明与文档，未修改本批检索或执行实现。
默认定位模式仍为 `legacy`，PRG 按 Run 显式启用。

## 冻结条件与对照边界

- 使用同一源码实现、阶段模型、推理配置、公开验证 profile、仓库输入、
  依赖镜像及独立评分器。PRG 与对照 runtime identity 均为
  `2d07c133404f25b3819424939d18e2f085332e1c5371a29e11a3a4eb2dcda266`。
- Localization 使用 deepseek-v4.1-flash、无思考、4,096 输出 token；Planner
  使用 deepseek-v4-pro-0813、high、8,192；Coding 使用 glm-5.3、low、8,192；
  Review 使用 deepseek-v4-pro-0813、high、16,384。保持原上下文窗口。
- 硬限制为 75 次逻辑工具、25 步、250,000 token、25 分钟；保留审批、测试保护、
  独立 Review。Run 创建、Worker 派发和恢复均核对持久化定位模式。
- 对照使用独立进程、临时数据库和新 repository ID，避免复用 PRG 图与索引。
  固定硬限制相同；费用可用容量按累计账本递减。该变化未成为 E05 对照的
  停机原因。原始 Issue、公开源码之外的评分材料不进入模型上下文。
- E06、E10 均没有产生实际补丁，不满足预设“显著进展”标准，因此不增加其对照。

## E05 成功路径及归因限制

批准范围是 `src/cache/cache-invalidator.ts`。初次补丁修复了继承失效方向，但
公开测试指出环境变体被过度失效。第二次修改引入 `Set<ConfigId>` 与
`readonly ConfigId[]` 的编译类型错误。第三次修改通过 build、typecheck 和
公开 test；Final Review 批准。三次验证和两次修正共用同一 Coding Session。

独立验收另行通过 Issue 复现、298 项原测试、完整性及其他冻结评分检查。
这些结果没有替代公开验证或 Review，也没有反馈给正在执行的 Agent。

对照 Planner 明确提出了源码修复方向，但 `candidateFiles` 中的 `symbol: null`
不符合可选字符串 Schema，格式纠正仍保留该值，提案最终被拒绝。对照未运行
补丁验收，不能由此判断其修复方向正确与否。

因此，当前证据说明 PRG 版本在 E05 完成了一次真实修复；**不能把对照失败
单独归因于定位差异，不能宣称 PRG 已稳定提高总体修复率**。一次成功也不足以
证明轻量 Localization 在所有复杂行为上都能完成定位。

## 请求可见性、建图与失败原因

实际 Localization 请求大小随调查增长：E05 为 16,682 → 43,651 → 61,118 bytes；
E06 已派发请求为 26,533 → 54,193 bytes；E10 为 27,055 → 51,452 → 66,103 bytes。
源码范围、完整 SHA、请求身份及省略信息保存在隔离审计记录中。

E05 的定位取得 23 次完整源码视图、复用缓存 33 次；E10 为 30 次和 29 次。
这些是调查取证计数，不能与账本物理 IO 混用。E05 初始图记录 20 次冷解析、
约 4.20 秒 parser 时间；E10 为 27 次、约 11.91 秒。Graph 的 wallMs 包含
调查间隔，不作为纯解析成本。热复用与修改失效的单元验收已覆盖，本轮没有
额外付费热缓存实验，也没有测得全仓事实召回率或语义关系准确率。

- **E06：报价与证据容量阻断。** 已看到公开回归测试、加载实现及部分消费者，
  仍未看到 compaction 实现、manifest 更新及 close 的完整行为链。
  第三次请求本身预计 31,643 token，所需下游容量为 230,418，合计 262,061；
  剩余 226,644，缺口 35,417。请求未发出。三类证据出现不等于关键行为链完整。
- **E10：关键消费者缺失及无进展。** Localization 已明确列出状态应用、汇总、
  事件和持久化尾部的证据缺口，补证又被预算报价关闭。Planner 仍把 dispatch
  层作为待核实修改目标。Coding 读到该层后继续查询，但未得到可支撑修改的
  状态应用证据；连续两轮无新证据后停止，未触发 Replan，未进入 Review。
  不能把这个结果归因于 Review 误拒。
- **图展示问题。** E10 的若干实际 `queryRelations` 结果包含
  `prg.facts=[]`、`omitted=29/26` 和不完整视图。需要进一步区分宿主已有事实、
  请求投影省略及模型看到的实现，不应把 query 成功视作有效证据已经展示。
- **费用报价问题。** E06 拒绝记录中，下游 token 非零而 continuation cost 为零。
  当前请求收费及累计账本均正常，未超支；该下游费用估算现象仍需定向验证。

上述问题在冻结期间仅记录，未临时修改预算、审批、Schema 或评分规则。
下一轮优先检查必要证据的阶段投影与下游报价、图返回中的源码/事实保留，
以及可选 Plan 字段和格式纠正的兼容性。不存在追加付费总结或完整流程重试。
