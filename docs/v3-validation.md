每个冻结批次一次完整运行。明确工程缺陷允许免费复现、最小修复和新冻结后再测；普通模型判断失败不会触发无依据重构。反复出现“修复导致新阻断”时停止本轮。只有工程及保护验收通过、真实协作证据改变决策、且 E10 严格通过公开验证、独立 Issue/原测试/完整性及 Review，才允许升级 3.0.0。

两次冻结结果分别保留如下。没有同批付费对照，不能宣称总体成功率提升或团队优于单 Agent。来源 SHA 有效不等于根因成立，流程恢复不等于修复成功。

## 本轮结束决定与剩余工作

停止继续生产代码修补及付费重试。R1 的两项确定性问题已在免费测试中重现并修复，R2 验证调查确实向前推进，但又遇到预算报价阻断。尚无证据证明 R2 是并发修复新引入的回归，也不能把它认定为模型能力问题。按照用户的收敛要求，本轮不继续进行“修复一个阻断，再付费寻找下一个”的循环。

- **下一项 P0：下游费用报价与失败诊断。** 按角色实际输入／配置输出价格及请求投影报价，保存被拒绝的操作清单、预约和具体缺口；先免费验证，不提高单 Run 上限掩盖问题。
- **后续性能审计：索引 IO。** 本次 10 个逻辑工具对应 271 次内部执行，需要检查缓存复用与真实重复读取；本轮未认定其中有多少属于冗余，也未改账面计数。
- **尚未真实验收：协作影响与修复。** 跨 Agent 反证改变后续动作、团队成果进入 Planner/Coding、严格修复成功仍缺真实证据。single / workflow 付费对照及 E05/E06 均 NOT_RUN。E02/E08 的会话、诊断和保护链路纳入免费回归，没有新增这两题的付费成绩。
- **现有实现边界：** 子 Agent 在同一 Worker 内有界并行；团队模型的无效结构化输出或截断当前明确停止，尚无独立的输出纠正策略。未知外部执行仍保留消费并阻断，不能通过恢复重新领额度。
