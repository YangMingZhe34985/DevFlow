## 免费回放与动态策略证据

1. **E07 原始消息错误**：保留原先九个已完成决策，随后用受控模型完成一次显式纠正、提交有效消息、接收者查询关系、返回团队结果。另有通用 A 反证 → B 改读 → 有效回复 → Coordinator 新委派测试。回复信用、未知回执、非法发送者、跨任务引用和重复投递均有负例。它们证明通信和持久化链路，不证明真实模型已经会这样协作。
2. **E01 原始编辑请求**：同公开源码 SHA 下，原展示范围 29–71 行；当前失败反馈为 58–79 行，包含缺失的 72–76 行分支，883 字节，新增读取和 HTTP 均为零。原补丁未被宿主改写，源码未变化。是否合法修对仍须模型再决定并经过测试。
3. **E01 公开基准与旧候选**：独立无网络 Docker 中 build 均通过；原始公开测试 89/91，历史候选 90/91。剩余陈旧 posting 过滤是基准缺陷未完成，不能称作补丁新增回归。详见 [审计](v3-e01-ownership-audit-20261013.md)。
4. **可选诊断生产链路**：真实数据库与 Docker、受控模型选择 `locateIssue → runDiagnostic → 编辑 → 正式测试失败 → 同 Session 修正 → 重测 → Review`；单 Agent 对照沿用不选诊断的既有路径。诊断开关关闭、任意命令、未列入白名单、未知回执和额度耗尽均拒绝。新诊断结果不改变最终验证权威。

开发期间发现并修正的集成问题也保留：

- 早期时间预检将瞬时剩余毫秒数作为固定期限，经过 DB 操作后误拒绝；改由实际模型准入选择期限，原 READ/SEARCH/TIMEOUT 故障测试仍实际派发。
- 注入的免费模型不应为报价读取真实 API 凭据；报价与实际绑定均使用明确的 injected 身份，未知价格仍按原费用政策拒绝。
- Docker 29 的旧 `--pause` 标记把弃用警告写进 stdout，导致镜像回执校验失败；使用官方默认暂停行为，保留 SHA 校验。
- 诊断资源最初只有局部随机名；现改为在派发前持久化 Run 隔离的精确身份。清理失败保留原错，未知回执不能获得新执行机会。
- 诊断输出字节必须与已有 IO byte 上限核算，不能只统计 Docker 执行次数。内部 copy/commit 文件系统操作标记 `UNOBSERVED`，不冒充精确磁盘 IO。
- 诊断运行中的 Session 仍有 pending tool call，不能直接作为下一请求投影；报价副本使用明确的 `BUDGET_ONLY/NOT_EXECUTED` 占位，实际历史和 Provider 的完整性检查不变。身份准备前先共享保留下游容量，所有实际 IO 仍独立计量。
- 全量默认高并发初跑 42 项失败，其中大量是宿主争用导致的 5 秒超时；限制测试进程为两个后仅余 14 项 injected 配置问题，随后修正。没有放宽生产 Run 期限。
