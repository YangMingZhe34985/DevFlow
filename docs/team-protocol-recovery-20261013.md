## 协议行为

### 证据引用

- `evidenceIds` 必须精确对应当前源码身份下、有效且对当前 Agent 可见的记录。文件 SHA、路径、近似 ID 均不能代替记录 ID。
- 错误反馈包含字段、错误 ID、当前可选 ID、路径/完整 SHA 及省略数量；列表最多 64 项。宿主不会模糊匹配、自动替换或静默删除错误字段。
- 校验覆盖 RESULT、PROPOSE_PLAN、SEND 等已有引用入口。调查者不能通过 RESULT 引用其他调查者未分享的私有证据。
- 当前源身份不符的旧记录不进入新请求。跨 Run/仓库证据、内容身份损坏、未授权引用和回复对象伪造仍硬拒绝，不当作普通拼写错误处理。

### 消息目标与生命周期

- 任务板呈现任务状态、Agent 状态和宿主保存的阻断原因。
- 向 BLOCKED/CANCELLED、未知、过期或错误归属目标发送消息时，消息保持未投递，返回具体字段与目标状态。不会自动唤醒、替换接收者或改变原任务。
- Coordinator 可在现有资源和任务上限内选择其他合法动作，或交接已有证据并保留缺口，或明确停止。此选择由下一次模型决策作出，宿主不强制生成计划。
- 已完成的调查者仍可接收关联当前任务的合法消息；若它已经承接新的待处理任务，旧完成任务的消息不能重新激活旧调查。取消旧任务也不再误杀该 Session 的新任务。

### 有界纠正与恢复

三个可纠正错误共享现有的每 Session 一次信用：`TEAM_REPLY_ID_INVALID`、`TEAM_EVIDENCE_REFERENCE_INVALID`、`TEAM_MESSAGE_TARGET_UNAVAILABLE`。兼容保留 `messageRecovery` 字段和 `MESSAGE_CORRECTION_EXHAUSTED` 停机原因。

1. 保存未执行的 CONTROL 回执和字段级反馈；同一模型答复中后续动作不能掩盖失败。
2. 下一次决策前持久化纠正操作 ID，再走正常 Scheduler 准入。资源不足不派发，不重置信用。
3. 模型可以显式纠正参数，也可以选择合法替代动作/结束。`resolved` 表示纠正决策已完成，不表示原消息已经投递；投递事实以独立消息和操作回执为准。
4. 无效调用仍累计无进展；一次纠正只给予有界决策机会，不作为实质证据，不清零计数。再次非法时只阻断对应调查者；Coordinator 自身耗尽信用则明确结束团队。
5. 重启后重放已确认回执，不重发原模型请求，不重复提交已成功动作。原信用、操作 ID、消费、截止时间和审批边界继续保留。

原有模型 Schema、消息配额、Run 硬限、独立上下文、审批、写权限和验证规则保持。可纠正协议错误不等于授权错误；没有把所有异常统一吞掉。

## 免费冻结回放

加载 E07/E08 最终持久化 TeamSnapshot 和已返回但未应用的原始模型决策，使用生产 TeamEngine、请求投影器执行。后续决策由受控模型提供；原消费和决策计数不重置，但此协议回放不证明原剩余预算能够负担新的真实请求。预算不足不派发另由回归验证。

## 保留的限制

本轮没有真实 LLM 通信实验。历史十题有效 AgentMessage 为 0 的事实不变；合成因果链及冻结回放不能替代真实轨迹。模型纠正后仍可能判断错误、缺证或预算不足；必要证据不足仍需明确阻断。

没有改变每 Session 一次信用的策略，也没有增加无限重试、自动复活、来源不明的 ID 修正或新的根因确认机制。依赖失败、消息/任务配额耗尽和未知外部执行仍按原保护规则处理。
