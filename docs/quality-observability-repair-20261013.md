## 证据与行为判断边界

交接保留当前源码身份、团队 revision、任务/消息/操作 ID、文件完整 SHA 和范围。假设、CHALLENGE 和未决项仍是待核实的模型声明，不因保存到宿主记录就成为权威事实。

- Planner 的 `planEvidenceIds` 对应本次请求实际显示的源码记录；旧团队 ID 不充当新的 Plan 引用。
- `RANGE_COVERED` 只表示同 SHA 下范围被展示，**不证明行为依据充分或根因正确**。
- `NOT_FULLY_VISIBLE` 表示相关范围尚未完整进入本次视图，不能解释成“源码不存在”。未转发的任务引用另行列出。
- 来源过期、缺失或内容哈希不一致时不静默丢弃反证。沿用既有预算准入，必要记录超限仍明确停止。
- Coding 保存历史调查和反证，不把其旧 SHA 当作可编辑的当前证据。是否需要继续读取、局部修改或申请扩大范围仍由现有 Agent/宿主协议决定。
- 不要求修改所有候选文件，不增加 Plan 必填字段，不允许凭调查状态扩大写权限，也不要求把每个历史假设都实现成新功能。

此轮没有解决通用语义层面的“假设是否正确”“每条 Issue 行为是否修复”自动判断。公共 Test、独立评分和 Review 的通过要求保持。

## 可观测性

团队请求事件现在包含与持久化投影一致的审计信息：最终请求指纹、序列化字节、估算输入 token、消息/工具/输出 Schema 字节、可用/保留/必要/省略证据数量、引用前后证据正文大小、历史保留以及摘要状态。

正文引用节约量只比较同一批保留证据，不包含省略收益，也不冒充实测计费 token。团队仍使用确定性工作状态，不能把它算成 LLM 摘要调用。

正常调查结束和执行中断分别保存 OUTCOME/INTERRUPTED 事件，包含：

- Agent 决策尝试、创建的 MODEL 操作、已确认响应、明确未派发、未解决派发和已应用决策；
- 成功消息数、宿主持有与模型实际展示的证据计数、缺少展示记录的旧回执；
- 具体失败操作、错误码、状态及原诊断。

一次 `generate` 不必对应一次 HTTP。没有 transport/费用账本依据时 `httpRequests` 为 null，不从决策数推算。取消或租约丢失导致审计事件无法追加时，保留原始执行错误，持久化操作回执仍是恢复依据。

Planner/Replan 的预算错误码和未派发状态已在上一轮资源修复中调整，本次沿用并增加实际请求证据审计，没有把旧修复再次算成新成果。仍需使用逐题公开诊断判断具体失败原因，未自动生成“模型判断错误”的结论。
