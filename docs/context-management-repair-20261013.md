第一批提交：`551a9f0`。阶段定向验收 32 项通过，其中包含第二批的摘要单元回归；第一批生产变更可单独撤回。

### 源码范围复用

Coding 与团队复用 `sourceRangeReferences`：只有路径、完整 SHA 一致，且某个可见记录完整包含另一个记录的原文范围时，才用引用替代重复正文。引用保留范围和末行分隔符；不将任意重叠范围拼成推测源码，不混用不同版本、不同文件或不一致原文。

引用的完整拥有者必须留在同一次请求中。团队删选证据后重新计算引用；Coding 固定拥有者，避免容量裁剪产生悬空引用。所有合法证据 ID、当前文件 SHA 和全文恢复能力保留。

完全相同的历史宿主记录去重；独特任务要求、反证、错误和当前批准计划继续保留。Provider 对原始候选的可测量容量拒绝允许回到投影选择，最终请求仍必须通过 Provider 校验；配置错误和未知错误直接传播。

### 团队短期工作状态

每次请求从当前 Agent 的持久化历史重建工作状态，包括：

- 当前源码身份下已尝试的调查方向及原始动作。
- 显式 RESULT 中的假设，以及尚未核对关闭的缺口。
- 历史反证说明与当前消息中的反证。
- 历史摘要哈希和源码身份变更记录。

调查方向与最近四轮动作通过下标引用去重。工作状态仍标为历史声明，不代表动作执行成功、根因成立或任务完成。旧源码或身份不明的记录保留历史引用，不提升为当前事实。单 Agent 对照模式向 Coding 交接相同工作状态。

SharedEvidence 的存储哈希、操作身份和归属信息继续持久化；模型视图复用顶层 Run/source 身份，不为每条源码重复发送存储字段。任务板已在 assignment 展示的目标也通过引用复用。当前代码正文、来源类型、路径、文件 SHA、范围、支持关系及证据 ID 仍然可见。

这是可恢复的结构化工作状态，尚不是跨 Run 经验学习，也不声称能语义理解所有自由文本假设。未明确关闭的历史缺口标为“未解决或待核对”，不自动制造额外完成门槛。

## 第二批：Coding 受控摘要

第二批提交：`4066eb8`。同时加入净收益检查：引用表示比完整已校验视图更大时保留原文；不恢复已失效源码。

修复 Unified Coding 绕过压缩配置的问题，复用现有 Schema、配置、回调、模型绑定、Scheduler 和 Session 检查点。

摘要只处理确定性投影已经按完整记录省略的旧成功读取；不处理当前必要源码、变更结果、审批、权限、预算、错误和反证。正文中的摘要解释属于假设，宿主只核验其来源、索引、哈希和原文引用，不认证解释正确。

请求前按真正序列化的摘要输入和配置输出报价，并保护主请求、现有纠正及下游容量。主请求估算使用当前投影和有界摘要增长空间，不按整个上下文窗口计费。未知价格不按免费处理。

摘要状态和次数在派发前保存。恢复不能新增额度；未知回执保留占用，明确未派发则释放对应 token 预约。截断、引用伪造、无法容纳摘要时回退静态视图。摘要加入后再次生成 Provider 投影，Scheduler 与真实请求使用同一指纹。

`semanticCompression.status` 可区分 `DISABLED`、`NO_ELIGIBLE_HISTORY`、`MAIN_PRICE_UNKNOWN`、`SUMMARY_BUDGET_RESERVED_FOR_MAIN`、`SUMMARY_LIMIT`、`REUSED`、`SUMMARIZED` 以及失败回退。跳过检查只记录简短事件，避免每轮重复保存全文摘要工件。

### 触发边界

此开关不会按累计 token 数强制付费摘要。静态去重负责减少重复输入；摘要负责在有空间、可核实来源且预算足够时，保留被省略历史的少量线索。摘要可能增加相对于纯静态视图的输入和调用费用，不能将其调用次数作为优化成功指标。

团队采用确定性工作状态，没有增加摘要 Agent 或摘要 LLM 调用。旧阶段摘要函数保留兼容；本轮没有将摘要强行扩展到 Localization、Planner 或 Review。
