### 动态工具契约

普通读取仍使用注册表原有 Schema；只有进入现有收尾刷新路径时，当前请求投影出的 `readFile` 最大/默认值变为 **16,384 字节**。注册工具原本更小的上限/默认值、行范围及自定义校验继续生效，不扩大约束。

模型看到的当前 Schema 与执行前校验使用同一 descriptor。超过当前上限的参数在 IO 前拒绝；省略 `maxBytes` 使用当前动态默认值。权限与审批检查仍独立执行。

刷新额度在参数有效、宿主授权通过后、IO 发出前持久化。错误参数不消耗刷新机会；成功纠正仍使用同一上限、原路径及已有纠正额度。恢复已消费的刷新状态不能再领取一次读取。

### 错误分类

保留既有错误码兼容，新增/补齐 `error.details.category`：

| 类别                   | 含义                         | 后续处理                                                                             |
| ---------------------- | ---------------------------- | ------------------------------------------------------------------------------------ |
| `INVALID_ARGUMENT`     | 参数不符合当前 Schema        | 在现有纠正与资源额度内修正，不触发权限收尾                                           |
| `EXPLORATION_LIMIT`    | 可选探索、刷新或操作预留耗尽 | 可选探索耗尽不单独关闭有证据的批准编辑；必要资源预留不足仍可要求收尾，不重新开放探索 |
| `AUTHORIZATION_DENIED` | 当前权限或批准范围确实不允许 | 保持既有受限交接，不能靠改参数取得写权限                                             |

Tool Executor 的基础 Schema 拒绝和策略拒绝也携带分类；原 `VALIDATION_ERROR`、`PERMISSION_DENIED`、`APPROVAL_REQUIRED` 和字段诊断继续可读。未知宿主拒绝保持保守处理。

### Session 恢复

按已有宿主 continuation 边界，在实际请求投影中失效旧的授权、收尾、时间和纠正控制提示；磁盘保留完整历史原文，请求视图以来源哈希保留过期控制记录引用，不删除错误诊断和任务证据。

只有宿主提供的新 `APPROVAL` 且批准计划确实变化，才解除旧授权交接状态。同审批的验证/Review/重复恢复不重置该机会。原预算消费、步骤、绝对期限、检查点、纠正额度、已消费刷新及未完成任务保持有效。

旧失败读取是诊断，不再被源码失效逻辑替换成仅含 `stale` 的空记录；成功的过期源码仍按原规则失效。
