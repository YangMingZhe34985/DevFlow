### 输入成本从哪里来

本批 140 次 HTTP 共 **1,266,034 token**，其中输入 **1,197,215**、输出 **68,819**；推理 token 是输出中的一部分，不能再次相加。

| 角色         | HTTP 次数 | 输入 token |
| ------------ | --------: | ---------: |
| Coordinator  |        19 |    165,683 |
| Investigator |        71 |    569,574 |
| Planner      |         7 |     38,606 |
| Coding       |        40 |    391,661 |
| Review       |         3 |     31,691 |

每次调用重新发送任务、角色约束、工具 Schema、计划、证据和部分历史，所以累计输入远大于仓库新读取量。Coordinator/Investigator 合计贡献约 61.4% 输入；仅优化 Coding 不足以解决整体成本。源码缓存节约物理读取，不会自动节约重复发送的输入 token。

最大实际请求 **71,952 字节**，未触及 96,000 字节限制。当前主要问题是多轮重复成本，不是本批再次出现单请求字节超限。输入占比高本身不证明全部输入都是冗余，仍需测量必要证据与重复内容。

### 当前长短期记忆的实际边界

完整历史、检查点、任务板和共享证据已经持久化；短期视图由 Coding/团队投影器重新构造。P0/P1/P2 是保留优先级，不是成熟的长短期记忆分层。请求级证据存储也不等于持续维护的 Agent 工作记忆。

没有证据表明 LLM 摘要丢掉了关键信息，因为本批根本未调用该摘要。确定性选择是否遗漏某个关键记录，需要 CTX-07 的逐请求审计。

### 建议下一轮上下文范围

1. 先冻结请求回放和测量：记录每类输入字节/token、重复范围、必要记录、可见引用及省略原因。
2. 分开保存权威任务状态、版本化代码证据和追加历史；为每个 Agent 建立持续的目标、假设、反证与未完成项工作集。
3. 统一投影接口，按完整源码单位和证据关系去重、选择；Scheduler 与 Provider 使用同一最终序列化请求和指纹。
4. 再考虑按需 LLM 摘要：必须有净成本收益、来源验证、失败回退和统一计费；审批、SHA、预算和验证结果不能以摘要替代。
5. 免费验收先证明必要信息保留、历史可恢复、过期证据失效及请求报价一致，再另行安排真实实验。

不以 prompt 变短作为唯一成功标准；同时检查未完成要求、当前反证、证据可追溯性、累计输入成本和行为决策。不得通过机械截断源码、删除反证或降低输出上限制造改善。
