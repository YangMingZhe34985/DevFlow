## 生产路径与可复用接口

`RunProcessor → ApprovalWorkflowRunExecutor → investigateWithTeam → TeamEngine` 使用当前 Run 租约、持久化任务板和原 Scheduler。团队成果仍进入现有 Planner/PLAN Approval。Coding 的 `locateIssue` 已能同步暂停写入、调用只读团队；`finishPhase`、Replan、Test/Review 反馈复用原 Unified Coding Session。

模型动作是提案，宿主执行是权威边界。保留现有 `DELEGATE/SEND/CANCEL/READ/SEARCH/RELATIONS/RESULT/PROPOSE_PLAN/STOP`，不为同义动作另建状态机。消息纠正只允许修改错误引用，不自动猜测 ID；所有尝试计入同一 Run。源码观察、诊断输出、模型解释均保留来源，不能据此直接宣布根因、测试或发布成功。

主动诊断仅从宿主公开验证配置选择现有检查，不能提交任意命令/环境/网络/新增参数。它是非权威观察，不能跳过正式完整 Validation 或独立 Review。实现必须复用现有 Sandbox 和工具策略，先验证只读/隔离、预算、操作回执及恢复；不满足时不开放能力。

## 交付及门禁

每阶段记录新增测试与失败，完整检查包括 lint、typecheck、test、build、format、公开文件、PostgreSQL/Docker 和旧生产链路。原始源码请求、账单和私有评分材料留在 Git 忽略目录。免费 Fake Model 只证明协议与编排；真实消息因果、修复率及三模式同预算实验均在单独授权前标为 NOT_RUN。

最终报告列出 P-01～P-05 的确定原因、未证假设、修复、回归、剩余风险、自治轨迹、冻结身份和后续实验报价；不以架构已实现宣称 v3.0 或真实质量提升。
